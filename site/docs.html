Architecture

Two halves. The converters in tools/sh2conv read the PC game’s files once, on the player’s computer, and write the pack. The engine in port/ reads the pack from the SD card and runs the game, with logic ported from the Director’s Cut exe function by function and the PC address of each function in a comment next to it.

  • The PC game: sh2pc.exe and data/ from the player’s copy.
  • The converters (Python, run by the packer) write the pack.
  • The pack goes to sdmc:/3ds/sh23ds/, about 1.3 GB.
  • The engine (C with libctru and citro3d) reads it on the console.

Build from source

You need Docker: Docker Desktop, or the Docker CLI with Colima on macOS. The build runs in a devkitARM image pinned by digest, and the same commit always builds the same sh23ds.3dsx, byte for byte.

Terminal
git clone https://github.com/ankushKun/sh23ds
cd sh23ds
./port/build.sh
./port/package.sh

build.sh writes port/sh23ds.3dsx and sh23ds.elf, and passes its arguments to make, so ./port/build.sh clean works. package.sh builds the CIA with bannertool and makerom and copies everything to dist/ with SHA-256 sums.

VariableDefault and use
SH23DS_BUILD_JOBS4, parallel make jobs
SH23DS_BUILD_IMAGEThe pinned devkitpro/devkitarm image
SH23DS_CIA_IMAGEsh23ds-cia-tools:1.0.0, built from port/cia-tools.Dockerfile on first use

Releases

The CIA asks for the 124 MB memory mode, the 804 MHz clock and the L2 cache (port/meta/template.rsf). The 3DSX gets whatever the Homebrew Launcher runs with. GitHub Actions builds both on every push and pull request.

  1. Bump VERSION, write what changed in .github/releases/v<version>.md and commit.
  2. Push a matching tag, such as v0.2.0.
  3. CI checks the tag against VERSION, verifies the checksums and publishes the release with those notes. The packer workflow pushes ghcr.io/ankushkun/sh23ds-packer with the same version and latest.

The QR codes on the install guide point at releases/latest/download/, so they stay valid for every release. tools/make_site_qr.py regenerates them if the repository or file names change.

The debug file

Lines in sdmc:/3ds/sh23ds/debug.txt change how the game starts. Delete the file to play normally. A common setup puts James in a room with a flag set and the readout on:

debughud 1
flag 32 1
spawn er01 -19250 0 21250 90 2
LineDoes
spawn <map> <x> <y> <z> <yaw> <mode>Start in a room. Mode 2 plays as James; other modes open the room viewer
stage <n>The stage for the spawn, otherwise taken from the room
flag <n> <0|1>Set a game flag before the spawn
item <id> <count>Give an item before the spawn
hp <n>Start with this much health
action <0..3>, riddle <0..3>Action and riddle level
enemy <kind> <x> <z> <yaw>Place an extra enemy, kind in hex (202 is a creeper)
wishBorn From a Wish flags, with stage 53 for its spawn
demo <name> <seconds>Play a cutscene from this point
movie <name>Play a movie
newgame 1Start a New Game without input
debughud 1The readout on the bottom screen (SELECT toggles it)
dumpframe <n>Save frame n as frame_n.bmp with its stats
perflog 1, memlog 1Log frame times and memory use

The converters

tools/make_pack.sh runs them in order and stops early unless sh2pc.exe has the Director’s Cut MD5, because several converters read tables at fixed addresses in that exe. To rebuild one part of the pack, run its converter on its own:

python3 -m venv .venv && .venv/bin/pip install numpy pillow pefile
.venv/bin/python -I tools/sh2conv/pics.py "Silent Hill 2/data" pack

The converters also write PNG previews and decoded events as JSON. The packer deletes them unless it runs with -e KEEP_EXTRAS=1.

Porting a feature

  1. Find the PC function in the Director’s Cut exe. The Ghidra project gets its names from the PS2 beta’s debug information and the Enhanced Edition source, as RESEARCH.md describes.
  2. Write the C in port/source with the PC address in a comment.
  3. If it needs data, extend a converter, then rebuild only that part of the pack.
  4. Check it with a spawn line in the debug file and a dumpframe.
  5. Run the smoke run from TESTING.md and update the notes for that part of the game.

Rules

Never commit anything that comes from the game: exe bytes, extracted assets, a converted pack, Ghidra databases or decompiler output. .gitignore covers the usual places; check git status before every commit anyway.

Pull requests should build in CI, pass the smoke run and keep the notes in port/*.md in step with the code. Code that ports an Enhanced Edition fix names the EE option and file in a comment.
