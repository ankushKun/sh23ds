Architecture #

Two halves. The converters in tools/sh2conv read the PC game’s files once, on the player’s computer, and write the pack. The engine in port/ reads the pack from the SD card and runs the game, with logic ported from the Director’s Cut exe function by function and the PC address of each function in a comment next to it.

  1. The PC game: sh2pc.exe and data/ from the player’s copy.
  2. The converters (Python, tools/sh2conv, run by the packer) write the pack.
  3. The pack goes to sdmc:/3ds/sh23ds/, about 1.3 GB.
  4. The engine (C with libctru and citro3d, port/) reads it on the console.

Build from source #

You need Docker: Docker Desktop, or the Docker CLI with Colima on macOS. The build runs in a devkitARM image pinned by digest, and the same commit always builds the same sh23ds.3dsx, byte for byte.

git clone https://github.com/ankushKun/sh23ds
cd sh23ds
./port/build.sh
./port/package.sh

build.sh writes port/sh23ds.3dsx and sh23ds.elf, and passes its arguments to make, so ./port/build.sh clean works. package.sh builds the CIA with bannertool and makerom and copies everything to dist/ with SHA-256 sums.

VariableDefault and use
SH23DS_BUILD_JOBS4, parallel make jobs
SH23DS_BUILD_IMAGEThe pinned devkitpro/devkitarm image
SH23DS_CIA_IMAGEsh23ds-cia-tools:1.0.0, built from port/cia-tools.Dockerfile on first use

Packaging and releases #

The CIA asks for the 124 MB memory mode, the 804 MHz clock and the L2 cache (port/package.sh, through port/meta/template.rsf). The 3DSX gets whatever the Homebrew Launcher runs with.

GitHub Actions byte-compiles the converters and builds the 3DSX and CIA on every push and pull request, keeping dist/ as an artifact. To release:

  1. Bump VERSION, write what changed in .github/releases/v<version>.md and commit.
  2. Push a matching tag, such as v0.2.0.
  3. CI checks the tag against VERSION, verifies the checksums and publishes the release with those notes, the install steps and the checksums. The packer workflow pushes ghcr.io/ankushkun/sh23ds-packer with the same version and latest.

GitHub creates a new container package as private. After the first packer push, make it public once in the package’s settings so players can pull it.

The QR codes on the install guide point at releases/latest/download/, so they stay valid for every release. tools/make_site_qr.py regenerates them if the repository or asset names change.

Running in Azahar #

Set the system to New 3DS. Put the pack in Azahar’s virtual SD card under sdmc/3ds/sh23ds/ (in its user folder), and add any file named sdmc/3ds/dspfirm.cdc, since Azahar’s audio doesn’t need the real firmware. Then open port/sh23ds.3dsx or install the CIA.

If the top screen stays black in the desktop app, switch the graphics API between Vulkan and OpenGL, or clear the shader cache for title 0000000000000000. A dumpframe line in the debug file shows whether the game drew anything.

Headless runs #

tools/lr3ds is a small libretro frontend for macOS that runs a build in Azahar’s libretro core without a window, with the software renderer, the New 3DS model (LR3DS_MODEL="Old 3DS" for the original), scripted input and screenshots at chosen frames. Its SD card is .lr3ds/save/Azahar/sdmc/, so the pack goes in .lr3ds/save/Azahar/sdmc/3ds/sh23ds/.

clang -O2 -Wall -o tools/lr3ds/lr3ds tools/lr3ds/lr3ds.c -framework OpenGL
export AZAHAR_CORE=/path/to/azahar_libretro.dylib
tools/lr3ds/run.sh 600 --frames 600 --shot 590:/tmp/title.bmp
tools/lr3ds/smoke.sh

run.sh takes a timeout in seconds and then any of these options. smoke.sh runs twelve scripted scenes, from the title screen to the pause menu, and writes a contact sheet to .lr3ds/smoke/. Run it before every pull request.

The debug file #

Lines in sdmc:/3ds/sh23ds/debug.txt change how the game starts. Delete the file to play normally. A common setup puts James in a room with a flag set and the readout on:

debughud 1
flag 32 1
spawn er01 -19250 0 21250 90 2
LineDoes

The converters #

tools/make_pack.sh runs them in order and stops early unless sh2pc.exe has the Director’s Cut MD5, because several converters read tables at fixed addresses in that exe. To rebuild one part of the pack, run its converter on its own:

python3 -m venv .venv && .venv/bin/pip install numpy pillow pefile
.venv/bin/python -I tools/sh2conv/pics.py "Silent Hill 2/data" pack

The converters also write PNG previews under bg/<area>/png/ and decoded events as JSON. The packer deletes them unless it runs with -e KEEP_EXTRAS=1.

Porting a feature #

  1. Find the PC function in the Director’s Cut exe. The Ghidra project gets its names from the PS2 beta’s debug information and the Enhanced Edition source, as described in RESEARCH.md.
  2. Write the C in port/source with the PC address in a comment.
  3. If it needs data, add to or extend a converter, then rebuild that part of the pack only.
  4. Check it in Azahar with a spawn line and a screenshot.
  5. Run tools/lr3ds/smoke.sh and update the notes for that part of the game.

Rules #

Never commit anything that comes from the game: exe bytes, extracted assets, a converted pack, Ghidra databases or decompiler output. .gitignore covers the usual places. Check git status before every commit anyway.

Pull requests should build in CI, pass the smoke run and keep the notes in port/*.md in step with the code. Code that ports an Enhanced Edition fix names the EE option and file in a comment.
